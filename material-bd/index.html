01 · Diferencias fundamentales

Dos arquitectos, dos enfoques

Una empresa necesita guardar su información y también que sus aplicaciones, servidores y servicios trabajen juntos. Por eso existen estos dos roles.

🗄️
Especialista en datos

Arquitecto de Base de Datos

Diseña cómo se almacenan, organizan, relacionan, protegen y recuperan los datos.

  • Define tablas, relaciones y estructuras.
  • Organiza almacenamiento y distribución.
  • Diseña seguridad, respaldos y recuperación.
  • Optimiza consultas y rendimiento.
  • Cuida la integridad y disponibilidad de los datos.
🌐
Visión global

Arquitecto de Sistemas de Información

Diseña cómo se conectan y funcionan las aplicaciones, servicios, usuarios e infraestructura tecnológica.

  • Define cómo se comunican las aplicaciones.
  • Selecciona tecnologías y plataformas.
  • Diseña integración entre servicios.
  • Define servidores e infraestructura.
  • Alinea la tecnología con el negocio.
Idea clave: el Arquitecto de Base de Datos organiza la información; el Arquitecto de Sistemas de Información organiza cómo funciona y se comunica todo el sistema. No compiten: trabajan juntos.

03 · Pregunta 4

Transparencia y autonomía en entornos distribuidos

¿Cómo puede una empresa tener datos en varias ciudades y consultarlos como si estuvieran en un solo lugar?

¿Qué es una base de datos distribuida?

Es una base de datos cuyos datos se almacenan en diferentes servidores o ubicaciones, pero se gestionan como parte de un mismo sistema.

🏢 QuitoServidor / fragmento de datos
⇄
🏢 GuayaquilServidor / fragmento de datos
🖥️ Consulta del usuarioAccede a la información sin conocer dónde está guardada

¿Qué significa transparencia?

El usuario no necesita conocer dónde están almacenados físicamente los datos ni cómo se encuentran distribuidos.

Fragmentación

Dividir los datos

La información se separa en partes. Puede ser horizontal (por filas) o vertical (por columnas).

Transparencia de localización

Ocultar la ubicación

El usuario consulta la información sin saber en qué servidor o ciudad se encuentra.

¿En qué se diferencia de los microservicios?

🗄️ La distribución se gestiona en la base de datos

  • El motor de BD administra distribución y ubicación.
  • Puede coordinar consultas y transacciones distribuidas.
  • Busca mantener integridad y recuperación ante fallos.

🔌 Los servicios se comunican mediante APIs

  • Cada servicio puede ser independiente y tener su propia base de datos.
  • Las APIs permiten intercambiar información entre aplicaciones.
  • La coordinación y consistencia requieren mecanismos entre servicios.

Ejemplo sencillo

Una empresa consulta los clientes de Quito y Guayaquil:

  • BD distribuida: el motor permite consultar los datos sin que el usuario conozca su ubicación.
  • Microservicios: un servicio de clientes puede comunicarse con otros servicios mediante APIs.
Ver respuesta académica breve de la pregunta 4

Un SGBD distribuido homogéneo ofrece transparencia porque permite consultar los datos como si estuvieran en una sola base, ocultando su ubicación y fragmentación. En cambio, los microservicios utilizan APIs para comunicar aplicaciones independientes, que pueden tener diferentes tecnologías y bases de datos. La integración desde el motor de base de datos facilita mantener la integridad y gestionar la recuperación ante fallos. En los microservicios, estas tareas requieren mecanismos adicionales de coordinación entre servicios.

04 · Pregunta 5

Gestión de concurrencia y control transaccional

Piensa en una transferencia bancaria: ¿cómo se asegura el sistema de que el dinero no desaparezca ni se registre a medias?

Ejemplo: transferir $100

Cuenta ARestar $100
→
Cuenta BSumar $100

Las dos operaciones deben completarse correctamente. Si se resta el dinero pero no se deposita en la otra cuenta, existe un problema de consistencia.

Atomicidad = todo o nada. La transacción se confirma completamente o se cancela; no debe quedar ejecutada a medias.

¿Qué es el protocolo 2PC?

El protocolo de compromiso en dos fases (Two-Phase Commit) coordina una transacción entre varios servidores o nodos.

1

Preparación · Prepare

El coordinador pregunta a cada servidor si está preparado para ejecutar su parte. Cada nodo verifica y responde si puede confirmar.

2

Confirmación · Commit

Si todos están preparados, el coordinador ordena confirmar. Si alguno no puede continuar, se ordena cancelar la operación.

¿Qué función cumple el Middleware?

👤 UsuarioSolicita una compra o transferencia
↓
⚙️ MiddlewareValida datos y aplica reglas del negocio
🗄️ Base de datosEjecuta consultas y registra información

El Middleware o servidor de aplicaciones es una capa intermedia: recibe solicitudes, valida datos y aplica reglas del negocio antes de enviar las operaciones a la base de datos.

¿Qué ocurre si falla un servidor durante Prepare?

Servidor A✓ Preparado
Servidor B✓ Preparado
Servidor C✕ Falla
Atención: el coordinador no puede confirmar que todos estén preparados. La transacción puede quedar bloqueada mientras se recupera el servidor o se determina la decisión final.
  • La operación puede quedar pendiente.
  • Se pueden mantener bloqueos sobre los datos.
  • Otras transacciones pueden tener que esperar.
  • Puede disminuir la disponibilidad del sistema.
Ver respuesta académica breve de la pregunta 5

El Middleware o servidor de aplicaciones se encarga de recibir las solicitudes de los usuarios, validar los datos y ejecutar las reglas del negocio antes de enviar las operaciones al motor de base de datos. Por otro lado, el protocolo 2PC garantiza la atomicidad de las transacciones distribuidas mediante una fase de preparación y otra de confirmación. Si un servidor falla durante la preparación, la transacción puede quedar bloqueada mientras se espera su recuperación o una decisión del coordinador, manteniendo bloqueos sobre los datos y afectando la disponibilidad del sistema.
